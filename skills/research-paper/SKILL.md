# Skill: Research Paper

**Purpose:** Turn analysis output into LaTeX a journal accepts and that compiles, on Overleaf or
locally: tables and figures generated by scripts, clean notes and captions, a working
bibliography.
**Load when:** creating or changing a table, figure, caption, preamble, `.bib` file or other
LaTeX output; fixing a compile error; fighting a page limit.
**Skip when:** the step produces no formatted output, or the task is only about the wording of
the prose (load `author`).
**Modifies behavior:** tables are written by scripts, never typed; every table gets a title and
notes; layout claims are checked on the rendered page, not inferred from the log.

**Sub-file:** `regression_tables.md` — load it when building a regression table
(modelsummary/tinytable in R, or a Python estimation package's table export).
**Related:** `author` for the prose around tables and figures;
`skills/empirical-analysis/plotting.md` for designing and exporting a plot;
`reference/overleaf_conventions.md` for getting files into Overleaf, if the paper is there.

## 1. Numbers come from scripts, never from typing

- **The analysis script writes each table as a `.tex` fragment** (`5_tables/tab_<name>.tex` in
  the standard pipeline), a sync step copies it into the paper's `tables/` folder, and the paper
  pulls it in with `\input{tables/tab_<name>}`. *Why:* re-running the script updates the paper;
  a number copied by hand goes stale the first time the analysis changes, and nobody notices.
  Never edit a generated `.tex` table by hand: fix the script and re-run.
- **Numbers quoted in the text come from the script too.** Have the script write a small file of
  macros, `\input` it in the preamble, and use the macro in the prose:

  ```latex
  % numbers.tex, written by the analysis script
  \newcommand{\NParticipants}{303}
  \newcommand{\EffectSaving}{0.14}
  ```

  Macro names are letters only (see § 6). If a number in the prose has no source, say so to
  the user rather than writing it.
- **One comparison per number.** Every result number in text, table note or caption states
  exactly one comparison and says which. A number averaged over treated and control units is a
  description, never a comparison. *Why:* the treated units are where behaviour moves, so pooling
  them into the reference shrinks the effect and hides it.

  ```
  # WRONG — "average" includes the treated group itself
  Treated participants save 12% more than the average participant.
  # RIGHT — one named reference group
  Treated participants save 12% more than the control group.
  ```

  When one violation turns up, check the whole document; they come in families.

## 2. Tables: the conventions

- **Every table has a title** (caption) placed **above** the table.
- **Every results table has notes** below it covering: the model or specification, the standard
  error type and clustering level, and the star legend (`* p<0.1, ** p<0.05, *** p<0.01` or
  whatever the field uses, defined once and identical in every table). Descriptive tables need
  notes when the aggregation level or the scale is not obvious.
- **Captions and notes are self-contained.** A reader must understand the table without the
  text: units, scales, sample, N, variable definitions. If the caption has to explain how to read
  the table's structure, fix the structure instead (add a column header, a panel label).
- **booktabs rules only:** `\toprule`, `\midrule`, `\bottomrule`. No vertical lines, no
  `\hline` grids.
- **Decimals:** 2 for continuous values, 0 for counts, the same within a column. No spurious
  precision (`0.034`, not `0.03412`), and text and table round the same way.
- **State the scale of the variable shown, not of its inputs.** A difference of two 0–1 ratings
  ranges from −1 to +1, and the note says so.
- **Never name a derived variable after one of its inputs** in a column header or note
  (`wtp_diff_benchmark`, not `wtp_rational`). *Why:* the reader takes the label literally.
- **Separate distinct analyses visibly** with panel labels (Panel A, Panel B), column group
  headers or a `\midrule`, so the reader never has to guess where one analysis ends.
- **Observation level:** demographics are reported per participant. For repeated measures, pick
  one level for the outcome and report both N participants and N observations somewhere.
- **Labels follow the filename:** `tab_weight_recovery.tex` gets `\label{tab:weight_recovery}`;
  figures use `fig:<name>`. Refer with `Table~\ref{tab:weight_recovery}`, never a typed number.
- **Wide tables:** wrap in `\adjustbox{max width=\linewidth}{...}` (package `adjustbox`), not
  `\resizebox`. *Why:* `adjustbox` only shrinks a table that is too wide; `\resizebox` also
  blows narrow tables up and distorts the font size. Count the columns before writing the code;
  from about seven columns on, plan for the width from the start.

## 3. Descriptive statistics tables (Table 1)

- **Continuous variables:** N, Mean, SD. Add the median for skewed variables, Min/Max only where
  the range tells the reader something.
- **Always SD, never the standard error of the mean.** It is the most common reviewer complaint
  about descriptive tables.
- **Bounded scales** (0–100, Likert): drop Min/Max (they sit at the bounds) and show a threshold
  share instead (e.g. "Share > 25"), naming the variable, the unit (participants or
  observations) and the threshold in the note.
- **Binary variables:** N and the share; the SD adds nothing.
- **Categorical variables go in the same table** as indented sub-rows under a header row:

  ```latex
  \midrule
  \textit{Gender}           & 303 &       &  &  & \\
  \quad Female              & 142 & 46.86 &  &  & \\
  \quad Male                & 158 & 52.15 &  &  & \\
  \quad Not reported        &   3 &  0.99 &  &  & \\
  ```

  The note says: "For categorical variables, N is the count per category and Mean the
  percentage." Use readable labels ("Female", "Yes"), never codes (`0/1`). Nominal variables get
  frequencies only, never a mean.
- **Treatment-level tables:** Treatment, N, Mean, SD, Median; group rows by treatment factor with
  sub-headers.
- **The text tells the reader what the table shows.** "Table 1 shows descriptives" is not a
  sentence about the data.

## 4. Figures

- **Export plots as PDF** (vector, sharp at any zoom); PNG only for photos, screenshots or plots
  with hundreds of thousands of points. How to size and style the plot: `plotting.md`.
- **Include at the printed width:** `\includegraphics[width=\linewidth]{figures/fig_<name>}`.
  Export the plot at roughly the size it will print, so its fonts match the text instead of being
  scaled down to unreadable.
- **Caption, label, notes** follow the table rules: caption describes what is shown, notes give
  sample, units and what the bars or bands mean (95% CI? standard error?).
- **After any change that moves the page count, check where the floats landed.** A figure that
  ends up on a bibliography page is a defect, not "interleaving". Fix it by moving the figure's
  source position earlier, not with `\clearpage`, which strands half-empty pages.

## 5. Bibliography

- **One `.bib` file per paper, inside the project**, exported from the user's reference manager
  (Zotero, JabRef, Mendeley). Claude adds entries there, never in a second file.
- **Never write a bib entry from memory.** Get it from the source: the publisher page, Google
  Scholar's "Cite → BibTeX", or the DOI through Crossref, which returns BibTeX for a plain URL:

  ```
  https://api.crossref.org/works/<DOI>/transform/application/x-bibtex
  ```

  Then check the fields (page ranges and capitalisation are often incomplete). If no source can
  be found, tell the user; a citation to a paper that does not exist is the worst error a
  Claude-written manuscript can contain. Last verified: 2026-10-07.
- **Protect capitals in titles** with braces: `title = {Evidence from {Germany} on {ESG} funds}`;
  otherwise many styles lowercase them.
- **Pick one system and stay with it:** natbib + BibTeX (`\citet{key}` "Author (Year)",
  `\citep{key}` "(Author Year)") or biblatex + biber (`\textcite`, `\parencite`). Use what the
  journal template uses. Overleaf runs the right tool automatically; locally, `latexmk` does.
- **Every `\cite` key must exist in the `.bib`.** An undefined key compiles to `[?]` or a bold
  key, and the log says `Citation 'x' undefined`. Search the log for it before saying a compile
  is clean.
- **What a citation claims** (canonical source, "e.g." for one of many, in-text versus
  parenthetical) is prose, and lives in `author`.
- For submission, ship the `.bib` together with the `.bbl` from the same compile as the PDF
  (`pre-submission-audit` has the details).

## 6. LaTeX traps Claude falls into

- **Escape LaTeX's special characters in generated text:** `%` (comment), `_` (subscript), `&`,
  `#`, `$`. In R, `sprintf("%.1f\\%%", x)` produces `12.3\%`. An unescaped `_` in a table note
  turns the rest of the note into a subscript and the words collapse without spaces.
- **Control-word names are letters only; a digit ends the name.** `\newcommand{\Ntreat2}` and
  `\newif\ifstudy2` break, often with an error far from the cause. Write `\NtreatTwo`.
- **A failed compile can still leave a PDF.** Read the exit code and the log, not the existence
  of a PDF, before saying it compiles.
- **No overflow warning is not "it fits".** Overlapping boxes, text running into a footer and
  slide content pushed off the page often produce no warning at all. To claim a layout is right,
  render the page to an image and look at it:

  ```
  uv run --no-project --with pymupdf python -c "import pymupdf as m; m.open('paper.pdf')[4].get_pixmap(dpi=110).save('page5.png')"
  ```

  (page index is 0-based), then read `page5.png`.
- **Over a page limit? Read the overflow page before cutting prose.** The spill is often
  bibliography entries, a stranded float or a one-word last line, each with a cheaper fix than
  cutting argument. In a numeric bibliography, every citation used only once is an entry that a
  single cut removes.
- **German text with pdfLaTeX needs this preamble**, or the PDF looks right but copies out wrong
  (`ä` becomes `a¨`, `ß` becomes `ÿ`), which breaks search, screen readers and any tool that
  reads the submitted PDF:

  ```latex
  \usepackage{lmodern}        % before fontenc
  \usepackage[T1]{fontenc}
  \input{glyphtounicode}
  \pdfgentounicode=1
  ```

  Check by copying a word with an umlaut (not only one with ß) out of the PDF.
- **Leave layout to the class.** No `\vspace` hacks, manual `\newpage`, or font-size commands in
  the body to make things fit; the journal will reformat anyway and the hacks break first.

## 7. Compiling

Two ways to check a build:

- **On Overleaf, if the paper is there:** Claude cannot see Overleaf's compiler, so the user
  compiles and pastes the error or the log ("Logs and output files").
- **Claude compiles locally**, the only way for a paper in the repository, which needs a TeX distribution (TeX Live, or MiKTeX on Windows,
  which installs missing packages on demand). Ask before installing one; it is several GB.
  Then: compile **in the project folder**, not with `-output-directory` (a stale `.aux` in the
  folder is read while the new one is written elsewhere, giving false `??` references); on
  Windows, an open PDF viewer locks the PDF, so build under another name
  (`pdflatex -jobname=check main.tex`) or ask the user to close it. A package missing locally is
  installed, never worked around by editing the source: the journal's and Overleaf's
  installations have it.
